CAN Message Utilities: E2E Profile 2 Check

CAN Message Utilities: E2E Profile 2 Check — Applies AUTOSAR E2E Profile 2 Check mechanism to an array of bytes previously protected using E2E Profile 2 Protect.

Library

Simulink Real-Time - Speedgoat

Description

The E2E Profile 2 Check block implements the receiver-side logic of the AUTOSAR E2E Profile 2 specification. It is responsible for validating the integrity and correctness of received messages protected using E2E Profile 2.

For in-depth documentation about the E2E Profile 2 please refer to the relevant AUTOSAR documentation.

Ports

Which input and output ports are available depends on the configuration settings in the block mask.

Input
Input Port

This input port is always available and its datatype (either CAN_MESSAGE_BUS, CAN_FD_MESSAGE_BUS or a uint8 array with a maximum length of 256 bytes) is configured by the Protocol parameter in the block mask.

Data ID List

This input port can be enabled with the Data ID List from Input checkbox in the mask. Data ID List input port expects an array of 16 elements of data type uint8.

Outputs
Status

This port outputs the result of the E2E P2 Check operation. The output can take one of the following values:

Status CodeShort NameStatus
0E2E_P02STATUS_OKThe received data is valid. Both the CRC and the sequence counter check passed, and there was no data loss detected.
1E2E_P02STATUS_NONEWDATANo new data has been received since the last check. The sequence counter in the received message is the same as in the previous message.
2E2E_P02STATUS_WRONGCRCThe CRC validation failed, suggesting the message data might be corrupted or altered during transmission.
3E2E_P02STATUS_INITALThis is the initial state of the receiver. It indicates that the system has not yet received or validated the first expected message.
4E2E_P02STATUS_REPEATEDA repeated message has been received. Although a new message was expected, the sequence counter has not changed, implying redundancy.
5E2E_P02STATUS_OKSOMELOSTThe received message is valid, but there are indications that one or more messages were lost in the sequence (i.e., a jump in the counter was detected).
6E2E_P02STATUS_WRONGSEQUENCEThe sequence counter is not in the expected range, which can suggest issues such as synchronization errors or an incorrect sequence due to wrap-around or message tampering.

Parameters

Data ID List from Input

If enabled, adds a "Data ID List" input port to provide the Data ID List from the Simulink® model.

Data ID List

If Data ID List from Input checkbox is disabled, the 16-element long Data ID List can be configured with this parameter.
