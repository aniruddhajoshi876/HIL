CAN Message Utilities: E2E Profile 1 Check

CAN Message Utilities: E2E Profile 1 Check — Computes and inserts a counter value in a CAN or CAN FD message payload.

Library

Simulink Real-Time - Speedgoat

Description

The E2E Profile 1 Check block implements the receiver-side logic of the AUTOSAR E2E Profile 1 specification. The block extracts the Counter and CRC from the received message, recalculates the expected CRC using the configured parameters, and compares it to the received CRC. If the values match, the data is considered valid; otherwise, an error is detected. The block also uses the Counter for plausibility checks, depending on configuration. Data ID, Data ID Mode, Counter location, CRC location, Max Delta Counter Init are all configurable to support flexible message layouts.

For in-depth documentation about the E2E Profile 1, please refer to the relevant AUTOSAR documentation.

Ports

Which input and output ports are available depends on the configuration settings in the block mask:

Input
Input Port

This input port is always available and its datatype (either CAN_MESSAGE_BUS, CAN_FD_MESSAGE_BUS or a uint8 array with a maximum length of 256 bytes) is configured by the Protocol parameter in the block mask.

Outputs
Status

This port outputs the result of the E2E P1 Check operation. The output can take one of the following values.

Status CodeShort NameStatus
0E2E_P01STATUS_OKThe last received data frame is valid. Both the CRC and the counter checks passed, and no frames were lost or duplicated.
1E2E_P01STATUS_NONEWDATANo new data was received since the last check. The counter value matches the previous one.
2E2E_P01STATUS_WRONGCRCThe CRC check failed for the received data, indicating possible data corruption or alteration.
3E2E_P01STATUS_INITIALThe receiver accepted the first valid frame and initialized its internal counter. Counter checking will be applied to subsequent frames.
4E2E_P01STATUS_REPEATEDA repeated frame was received. The counter value is the same as the last valid one, indicating a duplicate message.
5E2E_P01STATUS_OKSOMELOSTThe received frame is valid, but the counter indicates that one or more frames were lost (jump within MaxDeltaCounter range).
6E2E_P01STATUS_WRONGSEQUENCEThe counter jump exceeds the allowed MaxDeltaCounter range, indicating a possible synchronization issue or message loss.

Parameters

Counter Offset

Specifies the location from where the Counter is extracted. The value is expressed in bits and is zero-based.

CRC Offset

Specifies the location from where the CRC is extracted. The value is expressed in bits and is zero-based.

Data ID

Specifies the Data ID number used for CRC calculation. Data ID must be between 0 and 65535.

Data ID Mode

Specifies the way Data ID is included in the CRC calculation. Available options are BOTH, ALT and LOW. Refer to the relevant AUTOSAR documentation for a detailed explanation of these modes.

Max Delta Counter Init

Specifies the initial tolerance threshold for the difference between expected and received sequence counter. Refer to the relevant AUTOSAR documentation for a detailed explanation of these modes.
